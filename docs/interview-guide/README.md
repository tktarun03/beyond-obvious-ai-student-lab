# Explain the system you built

A portfolio becomes stronger when you can show evidence and discuss limitations.
Use a real completed slice from your fork; do not present this repository's scaffolds
as finished products or invent adoption, accuracy, savings or performance numbers.

| Question                          | Evidence to bring                                                  |
| --------------------------------- | ------------------------------------------------------------------ |
| Why use AI here?                  | One task that needs judgment and one handled by deterministic code |
| What if the model is wrong?       | A failed case, acceptance rubric and recovery behavior             |
| How do you protect user data?     | Server ownership check and a cross-user negative test              |
| How did you improve latency/cost? | Same-workload before/after measurements, including retries         |
| Can someone else reproduce it?    | Setup commands, synthetic fixture, commit and test output          |
| Is it accessible?                 | Keyboard/focus behavior and manual assistive-technology findings   |
| What would you change at scale?   | A measured bottleneck, explicit assumption and experiment          |

## A five-minute project walkthrough

Spend one minute on the user problem, one on the architecture, two demonstrating a
successful and a failing case, and one on the next improvement. State what you wrote,
what you adapted, and how AI assistance was checked. A small feature you understand
is better evidence than an unverified claim of a complete platform.
